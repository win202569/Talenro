## 3. 身份、命名空间与版本规则

生产IssuerID继续是现有字符串，逐byte匹配；不trim、不折叠大小写、
不添加alias、不将其重解释为SPKI/Name/SKI/AKI或本地Digest。
登记必须属于受控发布确定的部署范围；运行请求不能自由指定“可信部署”。

需要区分三个逻辑坐标：

- 部署范围：哪一个受控控制平面/部署的登记事实，不等同任意node UUID。
- 登记快照版本：该部署一次完整登记与状态发布的不可变版本。
- CA登记版本：稳定IssuerID下某一张 exact CA证书的不可变身份。

快照版本与CA版本不能混用；请求也不能通过自填版本绕过读取权限。
快照必须与真实受控发布的当前头及防回退记录一致；旧快照不能因签名仍
可验证就被重新当作当前资格。发布头倒退、同版本内容改变或撤回后复用
旧资格都必须拒绝。CA版本不通过字符串排序或取最大值自动选择。
逻辑键为(部署范围,IssuerID,CA登记版本)，其证书材料和关联字段不可改写。
同一键出现不同材料属于冲突，不采用last-write-wins或“后来的覆盖前面的”。

同一IssuerID可以保留多张历史CA证书，但必须逐张显式登记、逐版本选择。
同公钥、同Name或验证叶签名成功不能证明选择了哪个 exact CA版本。
本地引用是digest，生产IssuerID是字符串；两者不互作替代唯一键。

不可变材料与状态演进分离：撤回、失效或资格变化由新的受控快照记录，
不得修改旧版本证书，也不得因历史版本存在而推断当前仍可使用。
历史关联保留不等于当前授权资格保留。

现有(issuer_id,serial_bytes)约束不包含部署或CA版本。本合同不重新定义
数据库分区，也不把逻辑部署范围当作数据库已经提供的唯一性隔离。
在同一现有数据库中，同IssuerID跨CA版本仍共享这一唯一性命名空间。

## 4. 登记材料、签发关联和读取凭据

本节是逻辑合同，不新增Go类型、SQL表、配置字段、签名协议或公开API。
未来各字段必须由各自权威路径获得；字段齐全不等于事实可信。

| 事实组 | 必须绑定的内容 | 不能替代它的输入 |
| --- | --- | --- |
| 登记快照 | 部署范围、固定快照版本、完整性摘要、受控发布关联和当前资格事实 | 任意map、环境变量字符串、自报可信标记 |
| CA登记记录 | 精确IssuerID、CA登记版本、exact CA DER身份及其材料关联 | 同名、相同公钥、SKI/AKI、任意摘要 |
| 签发关联 | certificate/issuance身份、IssuerID、exact leaf身份、serial及选定CA版本的可审计关联 | 仅靠leaf可被某CA验证，或任选链中第一/最后一张 |
| 运行读取凭据 | 同一受保护读取下的authority版本、就绪/租约及前后稳定性 | 单独DB句柄、缓存epoch、回调、普通Ready=true |
| 观察范围 | 同一可信观察、证书/登记资格/读取凭据可用边界 | 请求方自填Now或“缓存永久有效” |

CA版本关联必须唯一且明确。旧数据库字段缺少该关联时，不允许靠名字、
字符串hash、链顺序猜测、同密钥签名或“唯一看似可用”的版本来补证明。

chain_der只是一条已存在的材料路径，不在本文中被自动升级为权威登记。
没有已批准的链编码/选择合同和签发版本关联，就保持证据不足。
chain摘要不等于选定CA摘要；不允许二者互相冒充。

登记发布需要绑定部署、发布权限、完整快照及其内容完整性。已有trust_bundle
或certificate_activate的fence不能仅换个名字就冒充登记发布证明。
专用发布语义及其可信获取方式必须通过后续独立设计、实施和真实验收。

## 5. 组件职责与未来数据流

职责分开，不把来源证明塞进一个接收任意输入的通用验证函数：

1. 受控登记发布边界：产出不可变版本登记、资格事实及发布关联；
   不负责证明某条旧证书行已经选定了其中一个版本。
2. 签发版本关联边界：建立证书/签发记录与 exact CA登记版本的可审计对应；
   不负责给未知历史数据补“最新版本”。
3. 受保护读取边界：取得同一部署下的一份固定登记及相关证书事实，
   由受控实例绑定其真实依赖，检查v7生产门槛及前后稳定性。
4. 材料与对应检查边界：使用真实nodeissuerbinding材料结果，与上述
   私有暂存事实逐项比较；不自行宣告这些事实来源可信。
5. 结果发布边界：仅在材料、对应、资格及最终读取检查全部满足后，
   输出该次观察下的有限兼容结论，释放中间材料。

不得把“结构一致性检查成功”命名或转换为“TrustedRegistry/生产兼容已证明”。
用户给出的Summary、verified flag或实现了某接口的对象均不是权威凭据。
公开工厂不得接受独立pool、登记快照、Ready回调、epoch和lease拼装后
宣称受控读取；测试替身不能被生产工厂接受。

一次操作固定一个登记快照，不在步骤间分别读取“最新登记”和“最新证书”。
读取连接/受控实例不能被替换；DBTX和回调只在受保护读取内使用，不保留。
若数据分别来自多个来源，它们必须与同一经验证的发布版本精确关联；
仅碰巧处于相同时间或epoch不够。

普通就绪检查不满足v7生产门槛。缺少真实已验收门槛时，生产能力必须
保持不公开、不可用；不能用“暂时开放，后面补检查”的方式推进。

## 6. 有限兼容结论的必要条件

所有下列条件均为必要条件；任一缺失不得产生成功模型：

- 受控登记来源、部署范围和固定快照版本已被真实来源路径证明；
  登记及证书事实属于该范围，不能跨部署借用。
- 生产IssuerID与登记记录及签发关联逐byte相等；对应CA登记版本唯一。
- 选定CA的exact DER摘要等于真实材料检查得到的CADERDigest。
- 签发关联与被查证书的leaf DER摘要、SPKI摘要、serial、证书/签发身份一致；
  不能把另一张证书或另一条签发记录的版本关联拼接过来。
- 存储serial与真实叶serial的实际长度、全部使用byte精确相等，
  使用最短无符号大端magnitude；不包含DER的符号00，不trim或再编码。
- Proposed.IssuerID/Serial符合现有
  main-selected-issuer-serial.ca-der-bound.v1及真实nodeissuerbinding结果。
  本文不修改该profile、两个域、hash输入、下层错误或原有责任。
- 登记资格及证书/行状态符合该观察下已批准的用途，未撤回、未失效，
  不因历史材料可检验就跳过当前资格检查。
- 同一受保护读取的v7来源、authority/部署身份、快照版本和租约门槛
  前后均满足；最终取消/截止检查完成之后才发布。

不能把生产字符串hash后直接与本地IssuerID比较，也不能从本地digest
反推出生产字符串。两个方向均需显式、可信且唯一的版本关联。

完整材料检查仍真实执行，不接受由请求方替代的预计算proof或Summary。
正常panic/失败/取消必须清理可达自有材料；输出和返回快照需要解除可变别名。
不承诺runtime隐藏副本、不可变字符串或物理内存已安全擦除。

兼容结论必须携带它实际对应的部署、IssuerID、CA版本、登记快照、证书
关联、本地profile和观察范围，不返回一个无上下文“兼容=true”。
该结论不证明密钥占有、完整identity/history、数据库提交或runtime授权。
全部既有Pending/Obligations保留，不能因为增加映射检查就删除其他责任。

兼容结论的复用不能超过证书材料、登记资格和真实读取凭据各自允许边界的
交集；无可验证时间边界则不允许缓存复用。不得延长原材料ValidUntil。
普通模型不保证并发访问；同步解析/外部调用的取消仅在可观察边界检查，
不能承诺硬实时中断、OOM或崩溃后的清理。

## 7. CA续签、旧数据与唯一性冲突

CA续签使用同IssuerID、新CA登记版本及新的显式发布。即使公钥和名字
不变，也不能覆盖旧CA版本或继承旧版本的材料引用。
保持原local profile；新exact CA改变引用preimage，不宣称数学上无hash碰撞。

已有证书只在证据证明其原CA登记版本且该观察下仍符合资格时可对应。
新登记版本不能追溯地把已有证书换绑到新CA。撤回和历史保留分别记录。

旧数据处理是拒绝规则，不是迁移实现：

- 缺登记版本/部署来源/可审计签发关联：证据不足，拒绝兼容。
- 两个版本都可验签，但无法证明原选定版本：冲突/歧义，拒绝。
- 未登记的IssuerID或CA版本：经可信完整读取确认后拒绝，不自动登记。
- 登记材料、摘要或签发关联矛盾：拒绝，不修正旧行或请求输入。
- 不自动批量回填、不按最新版本转换、不覆盖原digest/serial/issuer字段。
- 将来迁移必须有独立规格、授权、审计与真实数据库验收；本文不授权迁移。

同IssuerID的新旧CA复用同一serial时，现有数据库唯一约束仍必须生效。
不得修改/删除唯一索引、添加CA版本来静默扩大唯一命名空间、自动改issuer
字符串或删除旧证书行以避让冲突。上游签发策略必须满足现有约束；
真实插入冲突由后续受控写入流程处理，不由只读映射层“修复”。

只有形状正确、存在唯一索引或签名有效不能证明签发唯一性及部署可信性。
不存在的历史证据不能由设计文档或成功单元测试创造。

## 8. 错误与发布优先级

语义分类为有限且无敏感值的结果；这里不新增errors.New或统一旧错误码：

| 情况 | 结果与优先级 |
| --- | --- |
| 取消/截止 | 不返回成功结果，释放暂存材料；当前可观察取消优先 |
| 来源不可用、生产门槛缺失、连接/版本/租约变化 | 无法建立可信读取，不把它伪装成“登记不存在” |
| 已完成可信且完整的读取，没有登记 | 无映射，拒绝 |
| 历史关联缺失 | 证据不足，拒绝；不自动补值 |
| 重复对应、材料矛盾、错误部署/版本/issuer/serial | 冲突或错配，拒绝 |
| 材料签名、时间等原下层失败 | 保留原错误身份及typed链，不包装成兼容成功 |
| 所有条件满足且最终检查通过 | 仅发布该次观察下的有限兼容结论 |

就绪后置检查即使遇到无登记、证据不足或冲突也必须完成；
后置来源失败时不得发布暂存的领域结论。实际取消可终止查询并清理。
未知驱动/provider错误不转化为可信NotFound/Conflict，不泄露行、证书
原文、连接信息或未审查错误文本。

错误与阶段顺序固定为：初始可观察取消优先；其后是参数/预算检查，
再是可信来源及生产门槛的前检查。前检查成功后，在同一次受保护读取中
取得并独立持有材料，执行真实材料检查，再检查版本/登记/签发对应，
仅暂存领域结果。材料原错误优先于后续映射错配，原typed链不改写。
除实际取消外，领域失败也必须经过来源后检查；最终取消或来源后检查
失效优先于任何暂存领域结果。后检查成功才可交付有限成功或领域拒绝。
实施计划须忠实展开这些阶段，不得绕过lower或先发布再补来源检查。

这些是未来要求，不是本次已执行或通过的测试：

8. 前后发布版本/部署/authority/incarnation/lease变化、发布头倒退、
   同版本换内容、撤回后复用旧快照、连接更换、
   重复或漏调用读取回调；不发布暂存成功或暂存领域错误。
9. 完整有界复制、返回快照隔离、取消/截止/正常panic清理、caller不变；
   点数来自实际观察，不套用上一增量710作为固定目标。
