## 1. 用户目标与优先级

本轮继续完成 Windows 开发工具验证器与依赖模块隔离，保留完整性检查、进程归属、
输出保护及既有验收要求，不继续引入 Unix 原生监督帮助程序或系统托管依赖。
用户明确选择本轮只交付 Windows，将 Unix 标为暂不支持；不是将原 Unix 失败改称修复。

本文获批后，在以下原设计和对应实施计划中，仅替代四个开发工具入口的 Unix 支持、
Unix 正向验收及相关路由要求：

- `2026-09-25-c12-development-tool-isolation-design.md`
- `2026-09-25-c12-devtools-windows-powershell-addendum-design.md`
- `../plans/2026-09-25-c12-development-tool-isolation.md`

其他要求继续有效；冲突时本文优先，但不能据此扩大到其他 Bash 脚本、业务服务平台、
Docker 镜像平台或 C12 runner。历史文档保留原文，后续计划和恢复手册需标明本修订优先级。

## 2. 支持矩阵及拒绝合同

本修订仅涉及 `verify-devtools`、`check-tools`、`generate`、`verify-c11` 四个入口。

| 调用环境 | 本轮支持合同 |
| --- | --- |
| Windows + PowerShell Core 7.6.5 正式版 | 对应 `.ps1` 独立进程入口受支持，仍须通过全部适用验证 |
| Windows 5.1、其他 PowerShell 版本、预发布版本 | `.ps1` 在初始化和工作前拒绝 |
| Linux、macOS、其他 Unix、WSL 上的 PowerShell | `.ps1` 在初始化和工作前拒绝；相同版本也不能放行 |
| 任意平台调用这四个 `.sh` | 工作开始前拒绝；不是备用入口 |

“Windows-only”不表示 Docker 必须运行 Windows 容器，也不改变其他组件的部署平台合同。
Linux 容器可用于验证拒绝行为，但不能据此声称支持 Linux 开发工具流水。

四个 `.sh` 文件保留名称，改为最小拒绝入口。它们不再探测平台、解析仓库、检查模块、
创建临时目录或调用任何外部程序，不保留可达的旧工具执行路径。
只使用 shell 内建输出，stderr 一行提示，stdout 为空，退出码为 1：

`<入口名>: this release requires Windows and PowerShell 7.6.5.`

入口名分别为 verify-devtools、check-tools、generate、verify-c11。
此统一提示替代旧 Windows Bash 专属提示；与普通阶段失败格式并列为环境拒绝例外。
无论参数、工作目录、PATH、平台变量或模块文件是否存在，都不能转入工作流程。
不提供绕过参数，不自动转调 PowerShell、WSL、Docker 或其他脚本。

`.ps1` 保留已批准的 Windows 平台、精确 Core 7.6.5 正式版进程内检查，
版本/平台拒绝仍退出 1，使用原提示 `<入口名>: PowerShell 7.6.5 required.`。
必须在私有帮助文件加载、Add-Type、Git、Go、工具或 Docker 前完成检查。

## 3. Windows 架构及保障不变

- 四个 `.ps1` 都是独立宿主入口，不支持 dot-source 作为生命周期接口。
- 在任何工作子进程之前建立私有、未命名、句柄不可继承、kill-on-close 的 Windows Job，
  当前入口先加入 Job；初始化失败则停止，不回退为无监督执行。
- 保留初始化无子进程观察和正向对照、嵌套 Job、自然退出、工具失败、超时、入口强杀、
  外部 canary 和保留句柄确认退出的验证要求。
- 四入口之间使用当前已验证宿主的绝对路径创建独立子入口；不重新查找 PATH，不退回 5.1。
- 工具模块依赖齐备检查与完整 go mod verify 均保留；不联网补包，不接受缺缓存时跳过验证。
- 900 秒总预算、合计 4 MiB 保留上限、脱敏输出、环境恢复、错误码传播均不降低。
  C11 原 check-tools 900 秒、generate 600 秒外层预算不变，不增加跳过验证标志。
- 双模块边界、工具和传递依赖锁版本、显式 -modfile、根工作目录、Buf 嵌套调用要求不变。
  Goose 留在根模块；不建立 go.work，不升级或隐式降级依赖。

保留既有 Bash smoke 文件及 PowerShell C11 中对它们的调用。Windows 上仍可为这些
既有 smoke 子步骤准备 Git Bash；这不恢复四个 `.sh` 开发工具入口的支持。
不全局移除 Bash、不替换 smoke 宿主、不改变 C12 runner 的 PowerShell 合同。

## 4. 测试迁移与历史证据

活动测试随公开合同改为验证四个 `.sh` 在所有平台明确拒绝，不能只用源码包含关系证明。
在实际 Windows Git Bash 和现有 Linux 容器运行入口，确认退出 1、精确单行提示、stdout 空。
以专属 PATH 工具标记及只读/缺失模块场景确认没有 Go、Git、Docker、验证器、PowerShell
或初始化帮助程序工作事件；覆盖路径含空格、额外参数、环境污染和仓库外工作目录。
其他未安装 shell/平台只记录未实测，不伪造对应真实环境通过。

Windows 正向测试保持真实临时模块/缓存及实际运行时，不减少完整性、错误、超限和清理断言。
原 Unix 正向夹具不继续作为不受支持入口的成功合同；先归档其源码/测试版本及对应报告，
再让活动测试验证新拒绝合同。不把原失败断言改成预期成功来制造“修复”，也不对所有
Bash 测试全局 Skip。既有 Bash smoke 的测试仍适用。

以下历史事实必须保留并与新的拒绝结果分开报告：

- Linux 验证器上一轮为 14 PASS / 4 FAIL；失败是 parent-cancel、output-limit、
  stderr-limit、natural-exit-with-child。
- Unix 监督探针八项局部正向场景成立，但强杀监督进程自身会遗留子进程；
  负向对照检测到遗留不表示清理成功。
- Windows 最近一次专项为 28 PASS / 0 FAIL / 1 不适用 Skip，这是历史证据，
  后续实现修订仍需新一轮适用回归。

诊断报告位于 docs/roadmap 下的 2026-09-27 Unix 边界和监督可行性报告。
原始日志、探针源码与二进制仍留在忽略目录，不晋升正式帮助程序或提交到产品路径。
撤回 Unix 支持后，原 Unix 正向合同不再是本轮交付范围，但四入口拒绝合同必须验收。

## 6. 验收阻塞、非目标及回退

完整普通测试、完整 C11 和 C12 物理 gate 仍须先单独处理原事件并取得明确恢复授权。
I2/I3、Windows 物理验收、真实工具链及最终独立审查要求不降低，未完成即如实记录。
不得通过缩减平台范围宣称项目验收通过或获得 main 合并资格。

本轮不增加 Unix 监督程序、系统服务、cgroup 配置或新的清理权限；不修改防护、缓存、
C12 runner、生产业务逻辑、SQL 迁移及 Docker 资源协议。
当前工作区既有未提交代码和测试保留，须在实施阶段按新计划逐项处理；本文提交不夹带它们。

恢复 Unix 支持须作为独立设计和计划重新审批，并重新满足其进程归属、强杀清理、
输出上限、完整性及真实消费者验证要求；不能只删除拒绝入口就宣告支持恢复。
任何回退不删除共享缓存、不重置用户工作区、不抹除历史失败。推送及合并需另行明确授权。
