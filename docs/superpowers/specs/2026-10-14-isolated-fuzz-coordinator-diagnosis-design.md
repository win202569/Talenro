# 隔离 Go fuzz 框架诊断设计

日期：2026-10-14。基线：25d214fe95f45baeb1883e5075e334598fa97c91。
分支：codex/c12-b01-task9-coordinator。
状态：书面设计待用户审阅；仅获准编写、提交和推送本设计，未获准实施。

## 1. 目的与成功标准

在不修改正式工具链和产品的前提下，判断固定 Go1.26.5 的实际
CoordinateFuzzing 是否可能把正常预算截止记录为错误。已有探针只重演
错误分类模型，不能替代真正 coordinator、worker 退出及最终返回值证据。

成功是交付可恢复、可区分观察与人为干预的诊断结果，不是保证复现历史失败。
需要记录：实际父/子错误状态、分类前后 fuzzErr、退出来源、worker 收尾、
最终测试结果及隔离差异。不能复现、无法启动或控制不成立也属于有效结论。
历史 matrix3 的 Envelope 失败及 Pair 未运行继续保留。

## 2. 方案取舍

- 采用隔离副本：保留完整固定工具链副本，仅在副本加入诊断钩子。
  能观察实际框架；代价是构建开销、时序扰动和额外隔离检查。
- 仅重复已有模型：成本低，但不能增加实际 coordinator 证据，不作为本阶段方案。
- 升级工具链或改变验收方式：可能改变行为，超出当前范围，不采用。

隔离副本不是官方工具链升级，也不是验收工具链。不得把其输出称为原工具链
自然运行的结果；任何修复试验另行设计，不包含在本设计内。

## 3. 隔离和文件边界

实施获准后，使用新的本任务专属诊断目录，含独立 toolchain、cache、
fixture、receipts。源目录是现有固定工具链，目标必须是已解析、验证位于
本开发 worktree 的专属目录；源与目标不可相同或互相包含。
拒绝重解析点、符号链接或链接到原目录的文件；只复制普通文件和目录。
不得使用 hardlink、junction，不能对模块缓存做 overlay 或替换。

先记录固定源文件清单/hash，复制后验证，最终再次验证原目录未变。
诊断运行必须记录实际 go.exe、GOROOT、go version、GOOS/GOARCH、环境、
标准库来源和构建命令。显式使用副本，禁用自动下载；不改变全局环境、
PATH、安全设置、Go配置或 Docker 状态。独立 cache 不复用兄弟任务私有缓存。

可提交的是 PowerShell 复建脚本、最小诊断补丁/fixture文本、测试及解释文档。
工具链二进制、复制的源码树、缓存、临时程序、原始本机日志不提交。
项目已有 Go/SQL/module/验收测试不修改；诊断 fixture 放在独立目录，
不会被项目常规包发现。新电脑需自行具备已批准的固定工具链。

## 4. 诊断模式和实际框架路径

先验证副本未插桩时能启动并报告正确来源，再加入最小钩子，保持原错误
比较/更新逻辑不变。不添加新的错误抑制、重试或“修复”判断。

两类模式严格分开标记：

1. 观察模式：记录原逻辑实际读到的值，不刻意暂停 context 传播。
   记录动作仍会扰动调度，不承诺捕获自然竞态。
2. 受控模式：只登记此次 coordinator 的总预算 context；允许在这个父
   context 的 Done 已关闭、子取消尚未传播时暂缓传播，强制放大已有窗口。
   必须通过真实 coordinator 的截止选择分支和原 stop 逻辑，不用模型替代。
   这是人为调度的实际框架机制复现，不能证明历史失败发生于同一窗口。

设计约束：钩子必须仅针对已登记 context，不能暂停全局任意取消；只读取
原逻辑使用的值，不能以额外 Err 调用冒充原判断输入。记录每次 stop 的
来源、输入错误具体类型/哨兵身份、实际子 Err、原判断所需父 Err、旧/新
fuzzErr、stopping、干预标志和最终返回值；未读取的值标记未读取。
错误文本只辅助解释，不能作为身份判定。不得记录材料正文或凭据。

暂停不得跨越 cancelWorkers：context 取消可能持有父锁，而子取消会请求
同一父锁。须在原分类判断完成后、调用 cancelWorkers 前释放传播门，
并设置独立 watchdog、失败释放和进程上限。不能靠扩大测试时限解除死锁。
若无法不改变错误判断地实现此顺序，停止并修订设计，不改成伪造上下文。
具体钩子协议及其锁顺序测试必须在后续实施计划中写明再获准执行。

## 5. 对照、运行上限与证据等级

所有后续 fuzz 命令保留 -fuzztime=5s -parallel=1 -p=1 -timeout=30s；
冷构建时间单独记录，不冒充 fuzz 预算。每条测试命令 count=1，不循环重跑
直到通过。计划只允许每个指定诊断臂一次；失败停止对应臂并保留完整输出。
构建进程总上限10分钟，fuzz进程总上限60秒（外部保护，不扩大内部30秒）。

实施计划应分别列出：

- 未插桩副本的来源/启动对照，一次最小无错误 fuzz fixture。
- 插桩观察模式正常截止，一次同一 fixture。
- 受控父先截止臂，同一 fixture，经真实 coordinator 原判断保留截止错误。
- 同步截止对照，取消已传播后进入原判断，正常退出。
- 独立 fixture 回调的确定性 panic/crasher，经实际 worker、RPC、框架保留失败。
- 同一已登记上下文的正常停止/提前取消检查，以及有限错误身份和替换次序测试。

材料拒绝本来可能是合法 callback 返回，不能用 panic 伪称真实材料错误。
worker/crasher fixture 属故意注入的失败，不代表发现产品缺陷。
原有模型的结构化材料 Code/Cause/Unwrap 对照继续仅算模型级证据。
若无法在真实 coordinator 边界验证某类错误，应明确标为未验证，不能
把同文字 sentinel 或包装错误当真实 worker/process/integration 证据。

没有授权在本阶段重跑产品完整矩阵、Envelope/Pair或真实环境验收。
诊断成功不清除任何生产信任、C11/C12或其他既有验收门槛。

## 6. 可恢复结果与停止条件

每个臂保存源基线、工具链/补丁hash、命令、实际环境、UTC起止、退出码、
完整输出、干预状态、清理/worker收尾及超限记录。可提交报告保留结论和
必要证据摘要；原始日志在本机专属目录。时间展示采用用户 Asia/Tbilisi。
复建脚本须验证前置条件，不下载或安装依赖，不依赖聊天历史/旧私有缓存。

以下情况立即停止，不以自动替代方案扩权：源目录/hash变化；链接逃逸；
副本实际使用原 GOROOT；工具链版本不符；需安装/联网；钩子改变分类语义；
需扩大预算；无法释放传播门；工作进程未收尾；证据来源无法区分。
不自动删除目录；任何后续清理须验证确切目标，不能递归操作项目或缓存根。

结果分类只能是：实际自然观察、受控框架机制复现、模型对照、未复现、
运行失败或未运行。未经原现场状态不能断言历史根因，未经独立修复验收
不能声称已修复。将报告、状态和复建材料提交推送到现有开发分支，不合并 main。
