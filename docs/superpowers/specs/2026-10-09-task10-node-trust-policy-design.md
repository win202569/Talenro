# Task 10：节点信任状态隔离判定层设计

日期：2026-10-09。

状态：会话设计、本文及实施计划均已获用户批准。隔离模型已本地实现，
验证及审查实证见 `../../roadmap/2026-10-09-node-trust-policy-execution.md`。
未提交或推送；本文不是生产安全验收报告。

## 1. 目的、约束与依据

在现有 canonical 格式校验和条件性签名证据之上，建立可离线验证的
根信任、当前时间和历史状态转换规则，为将来平台接入提供明确边界。
用户选择暂按没有真实平台保障环境推进：本阶段仅设计隔离判定逻辑、
平台接口和测试模型，不声称 Windows 测试证明 Linux 生产安全。

依据：

- `2026-08-23-node-pop-control-plane-design.md` 第 7、7.1–7.3、12 节。
- `2026-10-09-node-state-format-contract-addendum.md`。
- `2026-10-09-task10-desired-signature-evidence-design.md`。
- 现有 `internal/nodecontrol/stateformat` 与 `stateverify`。

本文细化隔离模型，不覆盖或削弱上述生产要求。已有 Task 10 签名增量
仍是未提交的本地工作；生产兼容性 UNKNOWN，整体 B01/C12 验收未完成。

## 2. 方案选择与非目标

采用独立判定层，不把平台信任判断塞入签名校验器。扩大 stateverify
职责会混淆签名成立与当前授权；直接实现平台保障则缺少真实验收环境。

建议代码边界为新增 `internal/nodecontrol/statepolicy`，复用 stateformat
与 stateverify。包名是实施规划依据，不表示本轮已创建代码。

本阶段不实现：TPM/vTPM、可信部署验证器、跨重启可信时间源、双槽
持久化、硬件计数器提交、LocalSecurityLatch、TLS 集成、时间证明协议、
事件服务查询、生产 reader/provider、进程启动或隔离操作。
不新增网络协议、wire schema、依赖或锁文件，不改变已有签名接受语义。

## 3. 组件与数据流

### 3.1 精确输入和证据绑定

输入包括原始 Batch、独立部署锚观测、旧状态模型、时间观测和必要的
历史约束观测。调用期间输入不得被并发修改。

判定入口调用现有 stateverify.Verify，对本次原始输入重新产生证据，
而不是允许调用方单独提交一个“已验证”布尔值。再通过 stateformat
读取规则所需字段，并核对 node、epoch、对象坐标及 payload/envelope
身份与证据完全一致；不另写 JSON/JCS parser。

SignatureEvidence 只有部分坐标和摘要，不能凭其推断未携带的时间、
metadata sequence、密钥历史或撤销事实。解析材料本身也不是授权证据。

### 3.2 平台接口的语义边界

平台接口分为三类只读观测：

| 边界 | 必须表达的内容 | 本阶段的限制 |
| --- | --- | --- |
| 部署锚 | 节点、部署授权纪元、初始根身份、来源身份及可用状态 | 仅模型输入，不实现可信部署认证 |
| 时间 | 当前时刻、持久时间下限、提供方及观测身份、回退/不可用状态 | 不读取系统时钟代替，不实现跨重启证明 |
| 历史状态 | 旧状态身份、计数器身份/状态纪元、各对象高水位、根链前缀和密钥历史 | 不声称普通内存值或摘要具有硬件证明 |

接口的数据形状不能证明来源真实性。模拟适配器只置于测试代码，
不注册为运行时默认提供方。所有正向模型结果明确标为条件性结果；
无论模型输入如何，都不输出生产授权凭据。未来平台接入必须另行设计
来源认证与一致快照保证，不能仅把“模拟”标签改成“可信”。

### 3.3 纯判定和候选结果

核心在同一组显式观测上完成全部检查，不读取外部时钟、网络或存储，
不修改旧状态。成功返回独立拥有数据的候选模型，包含旧状态身份、
输入证据身份、拟议高水位、撤销历史、有效期边界及所依赖的观测身份。

候选不是提交回执、持久状态或可启动节点的 capability。输出不借用
调用方可变切片；失败或取消不返回部分候选。沿用已有 owner/Clear
惯例，不声称清除语言运行时内部副本或支持并发 Clear。

## 4. 信任与状态转换

### 4.1 首次建立及授权纪元

首次状态必须有独立部署锚观测，且与 Batch 的初始根、节点和授权纪元
一致。没有旧状态不自动意味着“允许首次初始化”；无法区分首次部署
与旧状态丢失时返回保障条件不足。

网络根链不能建立新锚、提升授权纪元或重置历史。旧状态已存在时，
更高纪元也不能走此更新入口；受信重新部署与 reenroll 不在本阶段。

### 4.2 历史根前缀与新增轮换

现有 stateverify 接受从初始 v1 开始的完整链，最多 32 次轮换。本阶段
保留此限制，不假称已支持生产从当前根开始的增量链协议。

旧状态模型保留已接受根前缀的版本、sequence、受签内容身份以及当前
根密钥集合身份。输入链必须与该前缀匹配；不能凭较高版本数字信任
替换后的历史。超出完整链上限返回范围不支持，不截断历史或换锚。

历史前缀仍进行格式和签名核验，但不要求已接受轮换今天仍在有效期。
新增后缀必须逐层衔接、版本 checked +1、sequence 严格增加、双门限
成立，且每个新增轮换满足 `issued_at <= now < valid_until`。
初始根集合本身不设置 wall-clock expiry。

### 4.3 对象高水位与内容身份

各对象流分别比较自己的版本和 creation sequence，不跨 root、metadata、
desired 对象流横向比较，也不以这些 sequence 替代 node checkpoint。

- metadata 提升版本必须同时严格提升自身 sequence。
- desired 提升 generation 必须同时严格提升自身 sequence；恢复路径不在本入口。
- 同一对象的版本与 sequence 均相同且 payload 身份相同，视为重复。
- 复用已接受版本或 sequence 却改变受签内容，属于已认证冲突。
- 低高水位输入拒绝，不降低旧状态；不能把任意网络重放直接当作本地
  持久状态已经回滚的证明。

“相同内容”使用同对象类型、作用域下 canonical payload 身份；envelope
摘要另外用于精确证据绑定。有效签名封装不同不自动构成内容分叉，但
每个封装仍须重新通过完整签名检查。现有 ActiveRootEnvelope 与本次链尾
必须精确相等的要求不变。

重复输入仍须满足当前时间和平台观测条件，不能靠幂等分支绕过过期。
真正无安全状态变化时返回 no-change，不建议推进计数器；时间采样和
诊断记录本身也不建议写 RollbackGuard。

### 4.4 密钥及撤销历史

metadata 必须是完整 snapshot；缺失密钥立即不再授权。已知同 key ID
的 public key、algorithm、not_before/not_after 不得改变；正常状态不得
逆转，已累计 revoked ID 不得重新成为 active/retiring。

累计 revoked ledger 只能追加，最多 4096 项，不得截断或通过网络重置。
尚在保留期的 tombstone 不得删除；完整 tombstone 至少保留 30 天，且
超过该 key 最后 snapshot 的 valid_until。达到容量限制时返回阻塞诊断。

scheduled 撤销要求已满足 retiring 历史及最后 snapshot/attestation 的
composite deadline；security_incident 提前撤销要求 exact open
online_signer_equivocation incident 绑定。旧格式字段或签名正确不足以
证明这些外部事实；历史缺失、跳版导致路径无法证明、最后签发期限
未知或 incident 状态不可验证时，返回保障条件不足，不能默认通过。

本阶段用显式历史模型测试这些条件，不实现事件服务或全局签发历史
采集。紧急撤销返回需隔离的诊断，不把结果当作可继续使用 desired 的
普通候选；实际持久化撤销与隔离的生产协调另行验收。

## 5. 时间规则

时间只取自同次显式平台观测；提供方不可用、观测来源不匹配、报告
回退或 now 低于持久 floor 时，不返回可用候选。跨启动连续性是平台
责任，不由应用比较两次 wall clock 冒充。

- 新接收轮换及当前 authorizing metadata 均须处于半开有效区间。
- desired 必须尚未到期，issued_at 不晚于 now + 5 分钟；保留既有
  签发时刻与 key window、metadata/key 上界约束。
- 重新检查 desired.valid_until 不超过
  `min(desired.issued_at + 24h, metadata.valid_until, key.not_after)`。
  候选有效性最迟在 desired.valid_until 结束，不能把此上界当作延长期限。
- 时间运算必须检查溢出，不能接受零值、无效范围或溢出后的时刻。
- 不要求 desired.issued_at 晚于较新 metadata.issued_at；兼容已有签名规则。

metadata、snapshot、时间证明及 HTTP Date 均不能更新、提高、降低或冻结
可信时间/floor。本阶段不新增时间证明 parser，也不验证 nonce/TLS；
相关生产 freshness 条件仍未实现，不因模型通过而被视作满足。

## 6. 结果及未来提交边界

| 结果 | 含义 | 状态处理 |
| --- | --- | --- |
| 条件性候选 / no-change | 模型规则成立或没有安全状态变化 | 不落盘、不授权生产 |
| 输入拒绝 | 格式、签名、绑定、有效期或网络高水位不符合规则 | 不改旧状态，不输出部分候选 |
| 保障条件不足 | 缺部署、时间、历史或平台来源保证，或超出本模型范围 | 保留验收阻塞，无降级替代 |
| 安全异常诊断 | 已认证内容冲突、平台报告回滚或可信状态自相矛盾 | 不生成正常候选；不直接调用生产隔离 |
| 已取消 | 调用取消 | 不输出部分候选，不修改输入 |

先完成结构/签名/身份验证，才能把远端内容标记为已认证冲突；未知格式
或签名错误不能用来指控可信状态分叉。多个失败并存时必须保持无候选，
错误优先级在实施计划中落实为确定性测试，不依赖 map 遍历顺序。

未来提交方必须重新验证旧状态身份未变、提供方连续性及时间仍有效，
并使用真正的原子并发控制，不能先比较后无保护写入。本阶段只测试
陈旧候选识别的纯模型，不实现提交器。

生产仍遵守完整 sealed state 的双槽、fsync、硬件计数器推进、启动恢复
协议，以及按层持久化信任的既有要求。这里的批量候选模型不能替代它们。
保留旧状态绝不意味着旧授权仍有效，也不允许时间保障失败后继续 LKG。

## 7. 验证设计与验收标准

测试使用固定签名样例、显式时间和测试专用平台模型。不得下载依赖、
访问网络、读取真实凭据、操作硬件、修改系统安全设置或启动真实服务。

必须覆盖：

1. 初次部署锚缺失/不匹配，旧状态丢失不能冒充初次部署，网络提高 epoch。
2. 0/1/32 轮换边界、历史前缀匹配与替换、新轮换过期/未生效、已接受
   历史轮换过期仍可核验，以及超过范围时不截断。
3. 各对象高水位前进/降低/复用、相同内容重复、不同有效封装、同版本
   内容冲突；不引入跨对象 sequence 比较。
4. 密钥属性改变、逆向状态、撤销集合删除、revoked 重新启用、过早删除
   tombstone、缺最后签发期限、缺 incident 证明及容量边界。
5. 每个时间边界的前一瞬间/等于/后一瞬间，desired 未来 5 分钟边界、
   时间不可用/回退/低于 floor、时间算术溢出；签名时间不能推进时钟。
6. 替换任一原始对象不能沿用旧证据；失败/取消无部分输出、不改旧状态；
   输出切片与输入隔离；陈旧旧状态或已到期候选在模型重检时被拒绝。
7. 依赖与调用扫描确认没有生产接入、wall-clock fallback、持久化/网络/
   硬件写入，模拟适配器不在生产源文件中注册。

实施阶段先针对新包运行隔离单元测试，再运行既有获准的定向回归：
stateformat、stateverify、serving、contracts、internal/readiness；authority
仅 TestBoundRead/TestCoordinator；store 仅编译不运行测试。具体命令与
新包测试执行范围在书面实施计划中审阅。本轮不执行任何测试。

不得扩展为真实 DB/Docker、全仓、C11/C12、bootstrap、PITR 或 race 测试。
已有安全阻塞不因本文解除。

验收成功只能表述为“在显式模型假设下，隔离判定规则通过指定测试”。
真实平台来源、跨重启防回滚、崩溃恢复、写入耐久性、TLS、生产授权、
整体 Task 10/B01/C12 以及合并 main 均不属于此验收结论。
