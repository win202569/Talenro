# 离线诊断入口迁移：待审阅设计

日期：2026-10-19。基线：aa8c11059fcba64801759082221b2718ba6decce。
状态：WRITTEN_DESIGN_PENDING_USER_REVIEW。
用户已批准制定离线诊断入口迁移方案；未批准本书面设计、实施计划或运行预算。
本轮仅只读调研和文档：无运行代码修改、模块导入、测试、目标、编译、安装、
新代理或独立审查。旧额度保持耗尽/冻结。全部五项能力标记仍为 false。

## 1. 目的、已知要求及假设

为今后的固定离线诊断建立一个明确、受支持的操作入口，使用已有证据支持的
存活会话确认和失败出口隔离；不再把历史 capture/driver 的磁盘 Outcome 当作
日常续跑接口。保留旧源码、原始记录、portable、审查、批准和失败结论的字节。

用户确认的边界：只涉及离线诊断，不做生产接入；先明确入口及验收范围；
必要资料提交到现有开发分支，换机能恢复进度，不恢复已消费运行权限。
设计假设：以后每个可运行 profile 仍须由独立批准的固定计划定义，不建立任意
脚本执行器、通用重放服务、后台常驻监督器或自动恢复运行。此假设供用户审阅。

成功不是“又通过一轮相同夹具”，而是：文档明确告诉操作者使用哪个入口；
这个入口实际只到达新的受管调用链；无确认、失败或 unknown 不能进入下一步；
历史入口不会被它调用；全新电脑默认只读检查，不自动执行或恢复确认。

## 2. 三种选择

| 选择 | 优点 | 代价与结论 |
| --- | --- | --- |
| A：新增受支持入口＋新的私有实现目录 | 正常调用收口；旧文件不动；可审查实际消费者和所有出口 | 需迁移路径、配置及测试归属；推荐，不能只套旧 driver |
| B：只在文档指定最新 driver | 变更最少 | 最新 driver 固定已耗尽的 Grant、raw 路径和历史身份，不是可复用入口；不选 |
| C：原地改旧 capture 或重定向原命令 | 旧命令看似兼容 | 改动冻结证据对应源码、混淆历史结论及额度；不选 |

推荐 A，但本文件不是 A 的实施批准。旧脚本保持可供读取的历史原件，不迁移
它们的运行状态；新代码不能通过别名、兼容参数或私有转发重新调用旧 Run/Slot。

## 3. 文件归属及不修改清单

拟新增的稳定操作入口：scripts/diagnose-offline.ps1。
拟新增私有目录：scripts/private/offline-diagnostics/，仅供该入口及固定测试使用。
私有职责分为：固定 profile 绑定/输入校验、Session/Ack 管理、受管出口、
确切对象执行与完成顺序。可保持分文件，不建立插件系统或可变 callback。
具体文件拆分和每份冻结输入由后续实施计划列全，不在此稿中创建代码骨架。

已有独立证明的机制可作为迁移来源，但不得直接 Import 最新历史 session.psm1：
该模块仍绑定旧 packet、冻结清单、固定 Grant 和本机依赖。应在新私有目录建立
新归属，以新的批准 profile、输入身份和记录路径连接；不得复制旧额度来运行。
每个新 profile 的步骤、目标及参数是计划冻结的数据，不是调用者传入的脚本。

不修改所有历史诊断 leaf、raw、portable、原 seam/codec/inbox、原审查及处置。
不接入 api/cmd/internal 等产品代码；不修改 scripts/verify.ps1、verify-c11.ps1、
verify-devtools.ps1 或 run-c12-integration.ps1，不加入默认验证链、CI 或 Docker。
这些现有入口属于其他验收范围，不能因新增一个脚本而扩大本次行为。

## 4. 操作合同

拟定入口使用固定枚举动作，缺省为 Inspect：

- Inspect：只读展示受支持的离线 profile、来源/冻结身份、依赖缺项和历史状态。
  不导入执行模块、不创建运行目录或 Session、不启动目标；不安装或下载依赖。
  便携资料只可用作说明，不能据其 Outcome 推导 CanRun、确认或剩余额度。
- RunApproved：只接受实施计划明确列出的新 profile 标识；不存在任意 ScriptPath、
  Command、Arguments、OutputRoot、RunId、Resume、Retry、Force 或 SkipValidation。
  标识是选择固定配置的数据，不是批准令牌；不能单凭命令参数或磁盘批准文件
  自行签发运行权。运行仍要求当前操作者/执行器具有另行明确批准的精确预算。
- 未知动作/profile、旧 Grant、旧 Slot 或恢复参数：在模块导入、创建目录和
  Process 创建之前拒绝。Inspect 不得暗含 RunApproved 的准备步骤。

实现计划须将每个可运行 profile 与一个新的固定输出命名空间、输入清单、
进程预算及有限期限绑定。输出已存在或尝试消费不明即拒绝，不通过自动换名、
重新初始化或删除目录再跑。第一版不提供无限生成新运行编号的接口。
运行 profile 不能只是 classification-red/green 等历史 Grant 的新名字。

这不是独立身份认证或防任意同进程恶意代码的安全系统。显式批准是工作流边界，
不是可从仓库文件恢复的 capability；本方案也不提供跨崩溃全局预算数据库。

## 5. 实际调用链与权限来源

受支持入口 → 固定新 profile → 单个存活运行宿主 → 私有 Session/步骤推进
→ 固定执行器＋受管出口 → 实际完成返回 → 私有一次性 Ack → 同宿主下一步。

顶层传输若另起捕获宿主，它只保留并清理自己直接拥有的 Process；目标进程由
对应存活执行器直接观察。不得宣称顶层独立观察所有后代。所有额外宿主均须计入
未来预算，不能把传输包装、准备宿主或最终验证宿主作为“免费步骤”。

Session/Ack 不序列化，不从文件加载，不跨 shell/进程转移。下一步真实消费入口
核私有引用、所属 Session、固定步骤/冻结代次、未消费/未撤销状态及剩余额度；
预消费在启动前 I/O 之前。完整成功文件、复制对象或同名字段均不替代确认。
全部正常完成 I/O、flush/关闭、原始输出及后置输入校验正常返回后才能登记确认。
Session 失败/unknown 即不可逆锁存首因、撤销未消费确认；终态不得恢复 Active。

固定受管路径只有一个出口状态。首次实际失败后，后续逻辑 Read/Parse/Save/
Complete/Publish/重新打开在文件访问前拒绝。清理只释放已持有的确切资源，
不为了记录清理再写失败台账；真实首因不被清理/汇总/次因替换。错误摘要有界，
若摘要或最终证据也失败，不重试、不寻找替代文件，保持 unknown/INCOMPLETE。

确切进程关联、退出等待、单消费者原始双流排空和已有有限清理约束不得放宽。
不加入 PID/名称重查、杀树、Job/watchdog、无限等待、启动预热或额外 readiness
等待。具体数值、总期限和静态 profile 的目标数由实施计划冻结并单独申请批准。

## 6. 兼容性和“唯一入口”的准确含义

迁移的是未来文档支持的正常操作入口及其实际调用链；不是篡改已完成阶段。
操作者文档应区分当前受支持入口、历史证据路径和禁止自动重放的旧命令。
不会把旧参数静默转换成新授权；不设置兼容 Run -Slot 或旧 Grant 别名。

“唯一受支持入口”不等于“仓库中其他 PowerShell 文件不可执行”。旧脚本不变，
用户仍可直接执行文件；不能声称本方案从 OS 层禁止了任意旧命令。若将来要求
技术性禁用旧脚本，必须另行处置冻结证据/兼容性，不能在此稿中暗自执行。

## 7. 验收矩阵：由真实新入口消费，不只测内部助手

| 情形 | 必须观察的结果 |
| --- | --- |
| 缺省/显式 Inspect | 无执行模块导入、目录创建、Session 和目标启动；资料读取不授予运行权 |
| 未知/旧 profile、Slot/Resume/任意脚本参数 | 在执行准备前拒绝；不调用历史 driver/capture |
| 可用下一步＋成功记录＋缺/错 Ack | 同一有效 Session、合法步骤、额度仍有余量时拒绝，Start 不增加；随后真实 Ack 可恰消费一次 |
| 复制/跨会话/错步/已消费确认 | 真实新入口全部拒绝，不消耗合法确认或额外目标 |
| 正常固定序列 | 所有完成动作先于确认；真实续接恰一次；原 seam 完整输出/trace 不变 |
| 真实预消费写失败 | 尝试已消费、Start0，不重建台账或返还额度 |
| 启动后真实记账失败 | 确切对象退出/双流/释放；失败出口仅1次尝试；后续逻辑 IO0，不发确认 |
| 实际输出失败 | 资源先收束、无 Ack、下一步拒绝，不能把已输出 PASS 当成放行 |
| 状态/捕获/最终证据 unknown | 停止后续新运行，不从已有成功文件复原权限，不重试原路径 |
| 全新电脑/仅便携证据 | 默认只读；依赖缺项准确报告；旧状态/引用/预算不可恢复 |

磁盘成功负例必须与正确步骤、Active 状态、未耗尽额度并存，不能只因 Budget0
或 Steps 空而拒绝后宣称已独立验证 C1。正负对照除提交的真实/缺失确认之外，
其他相关前提保持可解释；不能用伪造内部 Session、异常或生命周期 setter 补证据。

真实晚写、flush/close、宿主死亡或所有出口同时失败若不能安全诱发，必须标注
未动态验证；源码边界、普通真实 I/O 错误和状态消费证据不能冒称那些事件发生。
单个现有夹具再通过不等于新入口已接线，须保存新入口实际使用来源和调用记录。

## 8. 分层结论与 C1/C2

历史 C1/C2 及其原始 Important 结论不回填修改。新入口实现后可在独立记录中判定
“新离线入口的 C1 权威来源边界”和“新离线入口的 C2 失败出口隔离边界”是否满足。
只有新入口实际消费者证据、固定回归及获准独立审查支持时，才可提出这两个窄结论。
仅新增脚本、移植函数、改文档或本设计获批均不能关闭发现。

若新入口获得窄验收，旧代码仍作为不支持重放的历史资料保留；不得将其说成所有
旧脚本已修复或生产控制器完成验收。C1/C2 当前保持 open，R2/Minor2 仍延期；
SourceVerified/LiveActionsPerformed/RuntimeApproved/FormalAcceptance/
RealGateImplemented 全部保持 false。无 main 合并、发布或生产权限。

源实现、独立 oracle、批准规范/计划、实际消费、失败/unknown、完整审查和
原始数字文本/字节保留到开发分支。raw 保留原机 ignored；portable 仅资料，
不从其重建“原件”。换机先读 Inspect/恢复说明，不运行快照或恢复旧 Session。
