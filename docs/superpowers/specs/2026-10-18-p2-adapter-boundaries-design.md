## 4. 职责、数据方向与接口所有权

| 单元/角色 | 消费 | 产出与责任 | 明确禁止 |
| --- | --- | --- | --- |
| P2-A 换算器 | 调用者提供的固定整数 tick/frequency 声明 | 独立数值计划或拒绝描述符 | 读 QPC/UTC、取得真实能力、批准运行 |
| L 调用/兜底方 | 经独立准入的运行包及真实能力 | 冻结本次起点/截止，持有 W 与会话的确证控制能力 | 凭名字/PID 重找后任意结束进程 |
| W 独立监督方 | 同一冻结时基、有限控制消息、受约束会话能力 | 握手、截止/失联处置、独立观察摘要 | 在控制路径同步等待 C 的读取/写盘/finally |
| C 采集方 | 已武装且绑定的确切 T、两条独占字节读通路 | 有界字节前缀、EOF/exit 观察及故障摘要 | 决定自己的清理已证、延长截止或批准发布 |
| T 未来目标 | 以后单独批准的精确输入 | 目标自身输出/退出 | 本稿不提供目标脚本或历史载荷 |
| P3 接收边界 | 采集与监督各自的证据和完整性状态 | 未来独立真实格式的验证、持久化/读回 | 把真实字节传进旧 synthetic 构造器/store 冒称已验收 |

L/W 在受控会话 J 外，C/T 在 J 内；L 与 W 各持可独立停止同一 J 的受约束能力，
能力不交给 C/T。会话标签用于关联，不是身份认证；跨进程对象由各方持有的实际
能力和冻结绑定证明，不把序列化句柄值/布尔“已验证”当成可用权限。
纯数值对象与真实能力对象是不同接口，不能通过 cast、字段复制或标志升级。

逻辑接口分为：冻结数值计划、拥有会话绑定、启动许可、控制观察、原始数据观察、
最终证据交接。只有 P2-A 的数值接口在本稿定义为下一份计划候选；B/C 的具体 API、
控制传输和真实 wire schema 不属于此次可实施对象，须在各自设计中冻结后才可实现。

## 5. P2-A：仅计算的时基接口合同

逻辑输入为精确的被动 NoteProperty 对象，只允许以下五个字段：

| 字段 | 类型/约束 |
| --- | --- |
| Schema | 精确 Int32，值 1 |
| OriginTick | 精确 Int64，0..Int64.MaxValue |
| Frequency | 精确 Int64，1000..Int64.MaxValue |
| ObservedTick | 精确 Int64，>=OriginTick |
| StopTick | null 或精确 Int64，OriginTick<=StopTick<=ObservedTick |

Frequency 下限 1000 是本设计保守准入选择，只接纳至少每毫秒一个 tick 的声明；
不是 Windows 频率保证。所有声明都来自输入，不声称是该机器真实时钟。
拒绝额外/缺失/大小写变体字段、装饰标量、可执行属性、强制转换、负数和溢出；
检查对象/属性元数据先于取值，不调用调用者 getter/GetType/ToString。

逻辑输出固定八字段：Schema=1，Kind='timebase-plan-only'，Created（bool），
Reason（plan-created/invalid-input/range-refused/internal-error），Plan（对象或 null），
SourceVerified=false，LiveActionsPerformed=false，RuntimeApproved=false。
形状/精确类型/Schema/装饰错误用 invalid-input；整数范围、关系、低于最低频率
或算术无法表示用 range-refused；
普通可恢复内部异常保守返回 internal-error，不携带原异常内容；不保证灾难性恢复。
拒绝时 Created=false、Plan=null；仅完整构造计划时 Created=true、Reason=plan-created。
所有返回路径的三个事实/权限字段均保持 false，不返回部分成功计划。

Created=true 仅指整数计划可构造。Plan 固定八字段：OriginTick、Frequency、
DeadlineTick、StopAtTick、NaturalUntilTick、CleanupUntilTick、PublishUntilTick、
ObservedDeadlineExpired；后三个 Until 在 StopTick=null 时均 null。
ObservedDeadlineExpired 等于 ObservedTick>=DeadlineTick，不是“已经执行停止”。
输出数值/对象必须独立拥有，不缓存或返回输入/调用者扩展元数据引用。

所有 tick 只使用同一单位的有界整数：

- floorTicks(ms)=floor(Frequency*ms/1000)，ceilTicks(ms)=ceil(Frequency*ms/1000)。
  实现必须采用可检查溢出的商/余数分解或等价精确整数方法，禁止浮点乘除或先溢出再裁剪。
- DeadlineTick=OriginTick+floorTicks(120000)。
- StopAtTick=min(OriginTick+floorTicks(113500),DeadlineTick-ceilTicks(6500))。
  reserve 向上取整，执行/等待预算向下取整，允许早到一个 tick，禁止延长总期限。
- 存在 StopTick 时，s=min(StopTick,DeadlineTick)；
  NaturalUntilTick=min(s+floorTicks(500),DeadlineTick-ceilTicks(6000))；
  CleanupUntilTick=min(NaturalUntilTick+floorTicks(5000),DeadlineTick-ceilTicks(1000))；
  PublishUntilTick=min(CleanupUntilTick+floorTicks(1000),DeadlineTick)。
  起点/加法/减法均须检查范围；即使某个较小 min 分支可表示，也不吞掉未通过的算术校验。
- 输入 StopTick 可以晚于已到期截止，以表达迟到停止观察；不据此修复超时。
  Until 可能早于 s，表示窗口已经耗尽，不提供新的 natural/cleanup 时间。
- 任何真实消费者将 now>=对应 Until/D 按到期处理；等待值只能取阶段剩余与总剩余
  的较小值并向下取整为非负，不能把不足 1ms 的余额向上变成额外 1ms。

具名独立 literal 例（数值含义是声明，不读取机器）：

| 输入 Origin/Frequency/Observed/Stop | Deadline/StopAt | Natural/Cleanup/Publish | Expired |
| --- | --- | --- | --- |
| 0/1000/4/2 | 120000/113500 | 502/5502/6502 | false |
| 10/1001/120130/null | 120130/113623 | null/null/null | true |
| 0/1000/120000/120000 | 120000/113500 | 114000/119000/120000，窗口已耗尽 | true |

P2-A 不实现 P1 状态机、捕获事件、授权查询、会话/句柄封装或真实时间采样。
P1 归一化毫秒与 P2 tick 不能混作同一证据；P1 只可用作离线解释对照，不能以
synthetic-ms 或 Would* 字段替代真实时基、身份与停止能力。

## 6. P2-B：会话、启动和失联的拟议约束（未授权实现）

实际能力必须在任何目标指令运行前建立：输入/文件绑定准入、L/W 双向控制与
兜底能力、C 在受控 J 中保持未武装、读通路/容量预留、一次武装许可、精确 T 释放。
任一失败在释放前拒绝；释放后故障转为已拥有会话的受控停止，不重新发放工作负载。
不能用“启动后尽快加入”代替执行前归属，不以 exit0 或 W 自报证明全体成员已退出。

Windows Job 是候选能力，不是已验证实现；嵌套、继承、breakaway 与最后句柄关闭
行为有条件，不能据平台 API 存在推断本宿主兼容或清理已证。
[Microsoft Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
支持该选型依据，但具体能力、最小访问权及失败证据须由 B 的后续设计/计划单独验证。
不允许为兼容放宽保护或逃逸策略。原 cap32、观察访问 0x101000、inherit=false
不变；新增会话控制能力与原观察能力分离，不把外层 C/T 混入原 Root/Child 计数。

控制消息必须属于冻结版本/方向/会话/单调序列和有限长度，C 无权声明 W 的清理
结论。控制接收上限沿用 16，故障摘要最多 16 条、每条 1024 字节；最近心跳覆盖
固定槽，不无限追加。溢出进入停止，不借日志旁路扩容；心跳存在不证明实际读进展。
具体编码/最大帧和鉴别机制须在 B 自身设计中证明满足这些上界，未冻结则拒绝接通。

W 失联由 L 使用预持有能力处置；L 失联由 W 处置；二者都失效时仅依赖已验证的
会话关闭策略，不创造未授权回收器。没有存活独立观察者就不声称清理已证。

## 7. P2-C：原始读取与证据交接的拟议约束（未授权实现）

两通道各一条独占原始 byte 读通路、各最多一个在途读，二者同时推进；不得
先读完 stdout 再 stderr，或等待 exit 后才排空。标准重定向文档说明串行依赖有
死锁风险；本设计不采用其文本读取示例来重建原始字节。
[Microsoft StandardOutput 文档](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.standardoutput?view=net-10.0)

沿用每通道 1048576 字节、合计 2097152、单读 65536、数据事件 4096。待写队列、
在途块和已留存数据统一记账，不能各分无限缓冲；这不是整个 CLR 的内存硬上限。
返回 n>0 只保留实际 n 字节，n=0 才记该通道 EOF；短读、exit、取消请求均不是 EOF。
不使用行回调、文本解码/重编码或同时混用另一消费者。编码声明只供后续解释。

提交前检查容量；溢出整块拒绝并停止正向判定，保留实际已读但未留存的已知下界
和不完整状态。达到上限后的 EOF 确认仍只能是有界读；不循环丢弃到 EOF。
序号在实际提交处形成观察顺序，不恢复跨管道全局产生顺序；锁内不做 I/O/解析。

字节观察、exit 观察、监督故障、停止请求、停止已观察和成员最终记账分开记录。
交接 P3 的是有界证据与未知项，不是已完成归档或授权。真实格式不得复用 synthetic
记录入口；P3 未设计/获准前不发布成功含义的持久化标记。

## 8. 真实截止与失败语义（要求，不是本机事实）

未来 L 在整个调用发起时冻结真实 T0/Frequency/D；启动、握手、读取、停止、清理、
交接全在同一 120000ms 内，不在 release、换进程或重试处重新起表。
同机 QPC 用于间隔/截止，UTC 只作时间关联；不同线程极近 tick 的次序不能替代
事件序号。[Microsoft 高分辨率时间戳说明](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps)
给出时基性质，不证明本项目实际建立了可验证的跨进程绑定。

113500ms 前的停收点按第 5 节保守换算，保留共享 500/5000/1000ms，所有窗口
仍在 D 内。提前完成不把节省时间追加到 D 后；等于截止即到期，迟到旧时间戳
不能补成按时成功。调度/冻结造成超限要如实记录，不承诺 OS 硬实时。
任何等待都必须有界，不调用无参无限 WaitForExit，也不在有界 wait 返回后再
无限收尾；退出和重定向处理完成是两件事。
[Microsoft WaitForExit 文档](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.waitforexit?view=net-10.0)
明确这些区别；本设计要求单独的有界 drain 证据。

| 故障或未知 | 必须处置 | 不得声称 |
| --- | --- | --- |
| 授权/版本/时基/身份/所有权准入不足 | 目标释放前拒绝，保存已知原因 | 准备完成等于已获运行许可 |
| 读错、容量满、控制丢失、时基回退 | 封存已知前缀，触发已拥有会话停止，主因不覆盖 | 重试后成功抹去第一次失败 |
| 只有一个 EOF、先 exit、未知退出码 | 另一通道有界推进或超时，未知保持 null | exit0 等于双 EOF/全成员退出 |
| 停止请求已发送但未观察完成 | 记录 requested/unknown 及实际超限 | 已取消、自然完成或清理已证 |
| 总截止到期、stream drain 未完成 | timed-out/incomplete，清理未知除非有独立证据 | 再加清理时间后仍算按时 |
| 安全提示/新检测或前提漂移 | 停止，不修环境求通过，转交真实负责人 | 误报、安全清除或可继续 |
| 记录/读回/最终化失败 | 保留临时/失败证据，P3 不发布正向完成 | crash-atomic、掉电恢复或完整归档 |

故障主因保持 sticky；之后的清理或分类数据不能将失败转回正向成功。
采集完整、证据内部一致、真实清理、运行许可及用户验收分别判断，不互相推导。
