## 2. 支持范围

| 运行环境 | verify-devtools / check-tools / generate / verify-c11 |
| --- | --- |
| Windows 原生进程环境 | 仅支持对应 `.ps1` 独立入口 |
| Windows Git Bash、MSYS、Cygwin | 对应 `.sh` 入口立即失败，提示使用 PowerShell |
| 原生 Unix Bash | 保留对应 `.sh` 入口及原有完整验证要求 |
| WSL | 按 Linux 环境处理；不能代替 Windows C12 物理验收 |

Windows 不支持的 `.sh` 入口必须在启动 Go、工具、验证器或 Docker 之前以退出码 1 拒绝。
检查应位于入口最前部，只允许必要的平台识别；不自动转调 PowerShell，不提供绕过开关。
WSL/Unix 入口不自动回退到 Windows Go 或 Windows 工具。文档不得把未实测的 Unix 路径标为通过。

Windows 支持的调用形式为独立进程 `powershell.exe -NoProfile -File <入口.ps1>`。
直接 dot-source 公开入口不属于受支持的进程生命周期接口。
本附录不承诺终止任意外部启动器时，仍能监督已脱离它的 PowerShell 进程。

现有 Bash smoke 脚本不在此次取消支持或删除范围内。PowerShell C11 流程原有的 Bash smoke
调用保留，它是既有测试子步骤，不使 Windows `.sh` 开发工具入口重新成为支持路径。

## 3. PowerShell 进程归属

四个受支持 PowerShell 入口都必须在启动任何子进程前，建立私有、未命名、句柄不可继承、
关闭即终止成员的 Windows Job，并使当前独立入口进程加入其中。覆盖范围是整个入口，
不能只保护内层 verify-devtools 而遗漏随后生成、检查和 C11 阶段启动的进程。

允许新增一个仅供这些入口使用的私有 PowerShell 帮助文件，集中维护 Job 初始化和互操作定义。
加载该文件只定义函数；入口显式调用初始化。不得加载 C12 runner，复制其 bootstrap，
使用编码加载器，或把一次性原生探针及其可执行文件纳入正式实现。

初始化失败、加入 Job 失败或现有父 Job 不兼容时，在启动工作子进程前失败关闭。
嵌套入口各自承担完整验证责任，并测试嵌套 Job 行为；不使用跳过参数或复用“已验证”标志。
Job 句柄由入口进程持有到进程退出，不能提前关闭而误杀自身或正在运行的子步骤。
清理只作用于明确归属的 Job / 进程句柄，不搜索并收养外部进程，也不按进程名批量终止。

正常结束、工具失败、超时和入口被强制终止都必须验证其拥有的子进程已退出，外部 canary
仍存活。Job 只约束本机进程，不保证强制终止时清除 Docker 服务端资源；原 Docker 资源清理
协议保持不变，不因本附录宣称取得新的容器清理保证。

## 4. 不变的验证合同

工具模块仍需依赖存在性检查及完整 `go mod verify`；缺失、篡改、非零退出、输出超限和
超时均为失败。独立验证保留 900 秒绝对总预算及 4 MiB 捕获上限，正常输出和脱敏失败格式
沿用原计划。失败码继续区分普通失败 1、缺少可执行文件 127、超时 124 和 Go 自身失败码。

C11 的 check-tools 900 秒、generate 600 秒原阶段预算不变。外层预算先到即失败，不能因
内层独立验证预算较长而延长阶段。重复验证成本如实记录，不静默省略。
原生 Unix Bash 的进程清理、取消、完整性、路径含空格、退出码和脱敏合同保留，必须在
相应环境取得证据；Windows 拒绝测试不能替代 Unix 正向验收。
