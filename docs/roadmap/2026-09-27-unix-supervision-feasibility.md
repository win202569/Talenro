# Unix 监督可行性探针：Linux 局部可行，不能直接晋升产品

日期：2026-09-27。用户批准范围：仅在禁网临时容器进行一次性监督探针，
只操作自有测试进程，不修改正式入口或 C12。本轮遵守该范围。

## 实验假设与拓扑

假设：独立于 Bash 的监督进程可以在 Bash 被强杀后继续清理其启动的工具组；
同时在工具运行期间将 stdout/stderr 合计保留量限制为 4 MiB。

一次性驱动启动外部存活对照，以及 Bash 入口。Bash 启动 Go 编写的监督进程，
监督进程打开 Bash 的 Linux pidfd，核对父进程关系，随后为工具创建独立进程组。
工具再启动长存子进程。驱动为全部已知自有进程保留 pidfd，使用句柄信号及退出观察；
不扫描全机、不按名称终止、不收养外部进程。

监督进程使用 waitid 的 WNOWAIT 观察工具退出，在清理前不回收直接子进程，
从而在本次进程组终止操作前保留组长 PID 身份，避免“组长先回收再按旧编号清理”。
工具组清理完成后才 Wait 回收和完成输出读取。
输出只在内存有界保留，不把原始工具输出打印到终端；本探针不使用文件捕获 sink。

这是 Linux/amd64 原生帮助程序候选，并非纯 Bash 实现，不是已批准正式入口的组成部分。
使用 pidfd、waitid 等 Linux 接口；不声称其他 Unix 或 macOS 可用。
编译、源码分发与完整性信任如何纳入正式验证流程尚未设计，不能运行探针成功后直接复制上线。

## 环境与结果

固定官方镜像：
`golang@sha256:53eeac89074db483fdf0ab3be1df32bf6e47562263d2d0d6baa7f26acb4957dd`。
实际 Go 1.26.5 linux/amd64。容器禁网、只读根文件系统、cap-drop=ALL、
no-new-privileges、私有 /tmp、--init、--rm；只读挂载探针目录，不挂载仓库、
共享缓存、凭据或 Docker socket。程序和编译缓存仅在容器内生成。
构建及探针均有独立外层时间限制，探针工具预算 2 秒仅是实验值；产品 900 秒未变。

最终执行退出 0。八项正向场景均取得预期结果：

| 场景 | 探针结果 |
| --- | --- |
| 工具正常退出且留下长存子进程 | 状态 0；自有子进程退出 |
| 工具错误退出且留下长存子进程 | 状态 7；自有子进程退出 |
| 超时 | 状态 124；自有进程退出 |
| 强杀实际 Bash 入口 | 探针内部状态 125；监督程序继续清理自有进程 |
| 监督初始化后、放行工具前强杀 Bash | 状态 125；未产生工具启动记录 |
| stdout 超限 | 状态 1；合计保留 4,194,304 字节；自有进程退出 |
| stderr 超限 | 状态 1；合计保留 4,194,304 字节；自有进程退出 |
| 两路各 3 MiB、合计超限 | 状态 1；合计保留 4,194,304 字节；自有进程退出 |

每项外部存活对照均未被监督清理终止，最后由驱动负责清理。125 仅为本探针内部
取消状态，不是对正式入口退出码合同的修改。

两项负向对照均成功检测到预期遗留，随后通过保留句柄清理：

- 关闭父进程监测后强杀 Bash：工具及子进程仍存活。
- 保留父进程监测但强杀监督进程自身：工具及子进程仍存活。

这里“负向对照通过”表示检测器识别了泄漏，不表示该方案具有对应清理能力。
监督进程强杀场景明确暴露方案缺口；没有把它算作产品通过。

## 限制及下一步

本次仅证明监督程序仍运行、后代留在创建的进程组内时，局部退出及捕获策略可行。
它不是 Windows Job 的等价物，不能保证监督程序自身崩溃/强杀后清理，也没有覆盖
后代自行 setsid/改变进程组的行为。放行前取消只测了明确控制窗口，不证明穷尽所有
初始化与取消竞态。没有测试真实 Go 模块验证、消费者、完整流水或全部 Unix 平台。
内存捕获消除了本探针的 sink 文件，但不是对正式入口现有临时文件清理的修复证据。

不建议将本探针直接晋升产品。若继续，应先修订并审批 Unix 支持平台、监督器自身失败
保障、后代归属边界及帮助程序信任/准备方式；不能静默依赖系统级服务或提升清理权限。
现有正式 Linux 专项仍为上一轮的 14 PASS / 4 FAIL，任务 1 未完成，任务 2/3 未开始。
没有解除 Defender/I2/I3 阻塞，也没有执行 C12、完整 C11 或全套普通测试。
