# 开发工具隔离：逐项锁版本修订提案

日期：2026-09-27。状态：待用户选择方向的提案，不是已批准设计或实施计划。
用户已授权拟定修订方案；没有授权接受这 35 处差异。本轮只读已有证据及本机依赖清单，未修改模块、源码或脚本，未下载、测试、提交或推送。

## 目标与不可改变的边界

继续双模块隔离，同时尽量保持迁移前选中版本。六工具版本、Go 1.26.0/toolchain 1.26.5、根 Goose 库/CLI/驱动集合、完整性校验、进程归属、超时与输出保护不变。
不新增 go.work、跨模块 require/replace、替换版本或 exclude；不删除缓存，不调整 Defender，不恢复完整普通/C11/C12 执行权限。
原始设计和 Windows-only 修订继续生效；本提案只讨论如何处理完整模块图的版本差异。

## 新核对的事实与证据限度

原报告 35 项是“模块归属 + 依赖路径”的差异，不是 35 项均可接受的升级：根模块 28 处下降、2 处上升、1 个新增；工具模块 4 处下降。
前一轮八组 Windows 包闭包的集合与版本一致、脚本专项通过，是历史证据；不是第三方测试依赖、其他平台或完整模块图语义不变的证明。
完整模块查询仍存在缺失，带 -e 输出仅用于调查，不构成验收。

本轮读取原包闭包的 TestImports/XTestImports 和缓存中的固定版本 go.mod，确认：

- Goose 闭包中 modernc.org/sqlite 的 TestImports 含 github.com/google/pprof/profile；根 tidy 后显式间接保留的 pprof v0.0.0-20260115054156-294ebfa9ad83 声明 readline v1.5.1 和 demangle v0.0.0-20250417193237-f615e6bd150b。
- Goose 闭包中 google.golang.org/grpc/balancer/pickfirst 的 XTestImports 含 go.opentelemetry.io/otel/sdk/metric。根 tidy 后显式间接保留的 sdk/metric v1.44.0 声明 metric/x v0.66.0。
- 这些是依赖测试导入和已锁定清单的声明证据，不代表本轮执行了第三方测试，也不证明三个差异不可避免。工具模块可在裁剪状态下读到同样的清单而未选中相同子节点，说明不能仅凭清单推断活动完整模块图。
- 把所有原图节点直接 require 的方法已实际触发旧 genproto 与拆分后的 api/rpc 模块重复包；不能复用这种方式批量“消除差异”。

## 三条可选路线

| 路线 | 处理 | 代价及建议 |
| --- | --- | --- |
| A：精确恢复 + 最小例外（推荐） | 逐项尝试恢复 32 处下降；另外 3 项列为候选例外，逐项给出来源、确切版本和验证条件 | 最大限度保留版本约束；可能发现恢复某项会扩大根图或激活旧包，此时保持阻塞并报告，不能自动增加例外 |
| B：全图绝对一致 | 35 项均必须回到原状态，包括移除新增节点 | 继续研究裁剪和声明边界；与 tidy 的完整测试依赖要求可能冲突，目前没有验证过的可行方案，不能承诺可完成 |
| C：仅锁当前 Windows 实际包闭包 | 包集合和使用版本不变即可接受其余图差异 | 范围放宽最大，遗漏完整性校验和其他平台/测试依赖风险；不推荐，也不能用现有专项通过替代批准 |

## 例外与失败处理

正式修订应只列三个精确候选元组，不允许通配符、latest、自动升级或“其余差异一并接受”。
32 项恢复应按上游约束优先，再添加必要精确 require 的顺序研究；cloud/genproto 特别禁止无差别直接 require。
若恢复引入重复包、工具专属根依赖、实际包集合/版本变化或新的图差异，停止该项并补充证据，不强制替换依赖。
若调整后候选例外自然消失，则不再引入它；若新增其他例外，则重新请求审批。
缺失来源先作为准备阻塞报告。metric/x 是新候选模块，不包含在“原锁定依赖补齐”的笼统授权中；正式计划需明确其准备范围，再做校验和验证。不能联网运行验收。

## 正式设计与计划需要保留的验收条件

1. 原基线不可改写；记录两模块的完整版本比较及每项恢复来源。实际保留包版本与原基线一致；完整模块图只允许书面批准的精确例外，零额外差异。
2. 两模块严格离线 list -m -json all 均成功、没有 Error，包闭包无 Error/Incomplete/DepsErrors；-e 结果不能代替。
3. 显式版本约束在再次整理后仍稳定；若 tidy 删除用于锁版本的图级约束，先解释其来源和稳定方案，不循环手动添加来伪造成功。
4. 比较根普通、integration、Goose 及五工具的原包闭包；单独检查候选例外涉及的 TestImports/XTestImports 和清单依赖，不能把当前 Windows 运行包未变等同所有平台未变。
5. 根图不能为保持数字重新挂回五工具专属依赖；doubleclick 来源保留在工具模块。完整 go mod verify 及真实工具/生成验证仍必须按既有预算取得独立证据。
6. 补齐根模块专属 lint fixture；模块与调用链仍须原子提交。脚本专项、真实 lint/生成、最终独立审查以及被安全事件阻塞的门槛都不因本提案取消。
