## 问题与候选

当前 Windows PowerShell 5.1 的 Add-Type 源码编译在 Job 初始化前启动 csc.exe，
不满足已批准的“先建立进程归属、再启动任何子进程”要求。
用户允许评估不启动编译子进程的替代方式，不允许因此放宽保护、改变防护或运行受阻 C12。

本次检查已有 PowerShell 7.6.5 是否可直接完成同一明文互操作定义和 Job 初始化。
没有编码加载器、外部监督程序、新下载或第三方初始化库。
微软说明 Add-Type 支持通过源码生成内存程序集及调用原生 Windows API；这是接口依据，
不是“不会启动子进程”的实测替代：
[Add-Type 官方文档](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/add-type?view=powershell-7.5)。

## 环境与方法

- 本机候选：Codex 随附运行时中的 pwsh.exe，版本 7.6.5。
- 文件签名：Valid，Microsoft Corporation。
- SHA-256：362A356CE7F0940EC74F73A8FC2C990A2CC24A38A11C90BBD8ECA947110AD139。
- 对照：系统 powershell.exe，版本 5.1.26100.9444。
- 上述随附路径只用于探针，不应写入项目入口或视为新电脑已经具备的环境。

临时订阅进程启动事件，筛选父 PID 为探针自身的所有子进程，不只筛选编译器。
初始化后额外等待事件，再主动启动一个自有睡眠进程作为观察器正向对照。
没有事件但对照也未被观察到时，探针判失败，不能报告“无子进程”。

7.6.5 探针通过 PowerShell AST 只取得现有未提交 verify-devtools.ps1 中的
Initialize-DevtoolsProcessOwnership 函数定义并调用；不运行验证器主体、Go、Docker 或 C12。
随后查询当前进程和自有子进程是否属于该确切私有 Job，并检查 Job 句柄未设置继承标志。
这里只反射查询自有探针类型的私有句柄字段，不采用非公开系统 API 初始化方案。

取消探针的控制进程在 Job 外，保留测试父进程、子进程及外部 canary 的句柄。
自有父进程被强杀后，以有界等待确认子进程退出，检查外部 canary 仍存活；最终清理自有
测试进程。临时订阅在正常 finally 中移除，强杀时随订阅所属进程退出结束。

## 建议与剩余审批边界

7.6.5），使用 pwsh.exe 独立入口及同版本子入口；旧 powershell.exe / 5.1 提前拒绝并给出
环境要求，不自动下载、自动升级或静默转调，也不将 Codex 私有路径固化到项目。

这是新增开发环境前提，尚未获批；现有附录仍指定 powershell.exe，不能直接按探针修改
生产代码。若用户接受，需把版本检查、入口解析、子入口选择、新电脑准备说明和相应负向
测试写入设计/计划修订。原 Bash smoke 范围和 Windows C12 runner 均保持不变。

另一方向是维持 5.1 并增加预编译互操作程序集，但会引入构建、来源完整性和分发责任；
