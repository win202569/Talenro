# Implementation sequence

The original device-distribution, node-control, and account/entitlement phases are now grouped into the approved **C1 control-plane program** and split into five independently designed and accepted specifications. Each specification receives its own design document and implementation plan before production code begins.

1. **Project foundation, data dependencies, shared contracts, and health service — complete.** The pinned Go toolchain, PostgreSQL/Redis/NATS development stack, reversible schema baseline, generated Protobuf/OpenAPI/sqlc contracts, health and loopback metrics endpoints, deterministic verification, and end-to-end smoke test passed the Windows/Docker acceptance matrix. Redis 8.8.1 remains on the recorded unmodified AGPLv3 local-development path; production use is blocked until written legal approval or a recorded commercial license exists.

2. **C1.1 account principal, device identity, and configuration trust root — complete.** This specification establishes email/password and optional Passkey/TOTP/recovery authentication, configurable email verification, one-time device enrollment with proof of possession, isolated account/device token families, signed HPKE bundle primitives, monotonic trust versions, a Go reference client, and privacy-safe error reporting. Its independent exit condition is an enrolled device that authenticates, obtains and validates an immutable signed/encrypted test bundle from the primary API and two mirrors, rejects tampering/replay/rollback, and passes dependency-failure, concurrency, privacy, deterministic-generation, race, integration, and Docker smoke gates.

   As of 2026-08-22, both required clean-tree verification entrypoints have passed on Windows with real Docker PostgreSQL, Redis, and NATS: PowerShell at `d382adc` and repository-external Git for Windows Bash at `687ebe0`. Each completed fixed-tool checks, deterministic generation and generated-tree diff, unit/fuzz/race/vet/lint gates, migration roundtrip, live integration, a fresh E2E dependency lifecycle, conformance and Compose checks, the full tagged E2E package, and both shell smoke gates. Post-run checks found no owned container, network, volume, or task process and no tracked change. C1.1 is therefore **complete**; C1.2 advances only to `current design`, with no C1.2 implementation claim.

   This branch is not deployed and makes a pre-release replay-format cutover: every new device-token replay requires `family_id`, while legacy blobs are strictly rejected. Production release still requires quiescing writes, waiting for legacy idempotency retention or completing an approved bounded cleanup, atomically upgrading all replay readers/writers, and verifying the new format before reopening traffic. Mixed old/new rollout is unsupported, and rollback to the legacy format is prohibited after a new-format replay can exist.

3. **C1.2 node and POP control plane — current design.** This specification adds node inventory, outbound mTLS node agents, desired-state reconciliation, external-process Xray and sing-box adapters, and bounded health/capacity reporting. Its independent exit condition is a controlled process test proving desired state converges, unhealthy processes are quarantined, capacity is reported with bounded labels, and no tunnel-core binary is embedded or linked into the proprietary control-plane process.

4. **C1.3 entitlements, traffic ledger, and quota leases.** This specification adds Basic/Plus/Pro policy, device limits, allowed node groups, idempotent account/device usage accounting, bounded quota leases, and server-enforced hard stop. Its independent exit condition is a fault-injection test proving duplicate and reordered usage events do not change the ledger total, account totals equal device projections, and expired or exhausted leases stop access.

5. **C1.4 scheduling, tunnel credentials, and encrypted configuration distribution.** This specification adds authorization-first scheduling across country/node-group policy, health, capacity, failure-domain diversity and Rendezvous stability; per-device/per-protocol versioned credentials; deploy-before-issue rollout; and signed HPKE production configuration through the primary API and two mirrors. Its independent exit condition is a contract test proving only authorized healthy capacity is selected, credentials are deployed before publication and removed after grace, all three distribution sources carry identical bytes, and the client can continue from its last known valid configuration during control-plane outage.

6. **C1.5 five-POP end-to-end fault injection.** This specification composes C1.1–C1.4 in a five-POP simulation. Its independent exit condition proves unhealthy or full nodes are excluded, mirror and control-plane loss are tolerated within the ruled offline boundary, tamper/replay/rollback are rejected, duplicate usage and expired leases remain correct, and Xray and sing-box meter the same test traffic within the accepted tolerance.

7. **Tunnel Engine state machine, automatic/manual switching, and four-platform adapters.** This plan implements the stable Tunnel Engine contract above sing-box plus native Android, iOS, Windows, and macOS lifecycle adapters, with Xray and sing-box kept as separate operating-system processes and release batches outside the proprietary control-plane binary. Its independent exit condition is the same conformance suite passing on all four platform adapters for cold start, last-known configuration, automatic failover, manual switching, cancellation, and process cleanup. Distribution remains blocked on documented sing-box GPLv3+ complete-corresponding-source/store review and Xray-core MPL-2.0 covered-file/source-notice review.

8. **Catalog, Apple/Google/Web/crypto payments, and refunds.** This plan adds the product catalog and idempotent purchase, renewal, cancellation, chargeback, and refund lifecycles for each payment channel without granting entitlement from an unverified client claim. Its independent exit condition is a provider-sandbox contract suite proving signed event verification, replay-safe ledger transitions, entitlement convergence after out-of-order events, and complete refund or revocation handling for every supported channel.

9. **Referral rebates, affiliate commissions, and rewarded-ad rewards.** This plan adds abuse-resistant attribution and immutable reward accounting while isolating advertising from VPN traffic and tunnel processes. Its independent exit condition is a deterministic ledger test proving self-referral, replay, duplicate conversion, and conflicting attribution are rejected, valid rewards settle once, and ad unavailability or consent refusal never prevents VPN, account, payment, or invitation flows.

10. **Four-platform commercial UI, five-language localization, RTL, release, and store compliance.** This plan delivers native Android, iOS, Windows, and macOS product surfaces in Simplified Chinese, English, Russian, Persian, and Japanese, including RTL behavior, accessibility, packaging, upgrade/rollback, privacy disclosures, and store materials. Its independent exit condition is a signed release-candidate matrix passing native UI, localization/RTL, accessibility, installer/upgrade, privacy, and store-submission checks on all four platforms, with the Redis production license gate and the separate sing-box/Xray process, source, notice, modification, and application-store legal gates recorded as approved rather than bypassed.
