# 四项工具模块版本差异评估

日期：2026-09-28。状态：方案建议，尚未批准为版本例外，不是正式修订设计或验收记录。
用户批准的是影响评估；本轮只读取本地源码、既有基线和失败证据，没有运行依赖代码、下载、修改模块/策略、提交或推送。

## 目标与当前合同

继续完成开发工具隔离，保持业务与五个工具实际使用的包及版本不变。当前已批准合同仍是 32 项恢复、仅 root 三项条件例外；本报告不改变它。
本问题涉及模块版本合同，按 brainstorming 的架构修订路径评估。若选择修订方向，先形成正式书面修订，再修订原实施计划；保留 Native inline，不重做 Task 1。

## 证据边界与风险

- 完整严格模块查询此前仍失败；带 -e 的诊断值只能形成候选清单，不能代替完整查询成功。
- 四个较低候选版本的缓存文件本轮未找到，没有下载它们，未检查其完整源码差异或漏洞状态；不能声明安全等价。
- 未执行第三方测试、上游 goyacc、上游 progress 包或其他平台验证。不能把五工具当前未导入这些包推广为永不受影响。
- 将来增加工具功能、导入、测试或构建条件时，这些依赖可能进入实际包闭包；若发生，必须阻止沿用图级例外而静默改变实际使用版本。
- 根 28 项恢复还没有验证可行性；解决这四项不保证根模块不再遇到图裁剪问题，也不解除其他验收阻塞。

## 可选方向

### A：仅四项 tools 图级精确条件例外（推荐评估方向）

将原 32 项强制恢复中的 tools 四项单独改为“优先原版本；若严格查询、必要性和稳定性证明需要，则允许上表精确候选值”。root 的 28 项恢复和原三个 root 条件例外保持不变。不是将工具模块改成任意版本，也不允许删除这四个应保留节点来规避比较。
新增例外仍须同时满足：

1. 独立审批缺失候选的精确联网准备范围，不继承之前三个 root 候选的下载授权；准备和离线验证分离。
2. 两模块严格完整查询和图解析成功，所有成员迁移可解释；不接受 -e 部分输出。任何第五项 tools 差异、其他版本或跨 owner 使用停止报批。
3. 四项确未进入当前五工具实际包闭包；八组原包集合及实际使用版本保持不变，尤其 root/Goose mathutil v1.7.1 不变。增加回归约束，使未来图级例外进入实际包闭包时明确失败。
4. 分别记录活动父边、源码用途、来源校验、必要性、未验证范围；比较器验证证据记录确实存在，而非仅有非空 ID。
5. 正常 tidy 后四份锁文件及选中版本稳定；完整模块校验、真实工具版本、生成无差异、根 lint、脚本专项和独立审查全部保留。无 dummy import/tool、回挂根专属依赖、replace/exclude、跳过或放宽时限。

收益是接受拆分后的精确图差异而保持当前实际包不变；代价是明确接受四个较低图节点，未来用途变化需要重新审核。该方向尚未证明能通过所有门槛，不是依赖安全认证。

### B：维持工具零例外，暂停这条迁移路径

保留原版本要求，继续只读寻找能经 tidy 保留的真实上游来源；找不到时保持未验收。不得凭空添加用途，也不能在未批准情况下升级上游或合并回单模块。收益是不扩大版本规则；代价是当前模块隔离不能完成，且尚无已验证的稳定约束方案。

### C：仅比较实际包，忽略其余图版本（不推荐）

实施较容易，但会失去对未来包用途、第三方测试和图变化的精确约束，明显超出此次四项问题，也违背原完整图版本合同。不作为推荐修订。
