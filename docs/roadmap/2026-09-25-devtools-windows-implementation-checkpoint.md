## 本轮证据

固定 Go 1.26.5，GOENV=off、GOTOOLCHAIN=local、GOPROXY=off、GOSUMDB=off；仅用专属临时
模块、缓存和自有测试进程。命令：

```text
go test -v -tags=e2e ./internal/e2e -run '^TestDevtoolsVerification(PowerShell|Bash)$' -count=1 -timeout=5m
```

最新专项回归退出 0，用时 63.767 秒，28 个子用例 PASS、0 FAIL、1 个不适用用例 Skip。
覆盖真实缓存完整性、缺失和篡改、退出码、隐私输出、超时、
自然退出、父进程取消、超限、初始化失败、实际 5.1 拒绝及 7.6.5 运行、两个 Git Bash 拒绝入口。
PowerShell 下不适用的 Git 包装器取消子用例为 Skip，不作为取消成功证据；该平台现测明确拒绝。

额外边界证据：

- 5.1 拒绝窗口没有子进程事件；观察器的专属正向对照确实被捕获。
- 真实私有帮助文件加载不初始化类型；初始化窗口没有子进程事件；确切 Job 归属和句柄
  不可继承成立；真实嵌套 Job 初始化通过；观察器有正向对照。
- 超时/父进程取消后自有句柄确认退出；外部 canary 存活。
- 只在测试副本移除依赖齐备检查，会使缓存完全缺失的模块仍得到 Go 验证成功；原实现对应
  用例明确失败。此变异证明齐备检查不能省略，不将变异副本视为合法实现。
- 成功和 Go 失败后均恢复入口原有 GOPROXY、GOFLAGS、GOWORK、GOCACHEPROG；只观察固定
  测试值，不采集用户真实环境内容。

## 测试驱动与实施裁定

旧版拒绝先失败：实际 5.1 返回 module 阶段错误；加入版本检查后版本测试通过。
Windows Bash 拒绝先失败：两个实际入口均进入 module 阶段；加入最前部拒绝后通过。
输出超限先失败：旧实现等进程退出再查大小，长存超限进程返回超时 124；改为运行中有界
捕获后返回失败 1。超限测试副本预算改为 30 秒，外部测试仍有 15 秒限制，以区分输出限制
与 2 秒初始化/读取竞争；产品 900 秒预算没有改变。

内存捕获的 4 MiB 是 stdout/stderr 合计上限，比旧代码逐流检查更严格；另有固定大小读取
缓冲区开销。它避免落盘捕获持续增长或强杀遗留文件，但仍需后续消费者回归。
